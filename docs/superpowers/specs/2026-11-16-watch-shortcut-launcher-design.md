# Apple Watch 捷径入口设计

## 目标

让用户从 Apple Watch 打开一个水量输入界面，默认显示 `197ml`。水量正好是 197 时直接确认；需要调整时直接修改数字再确认。实际的数据读取、iCloud 写入和局域网同步仍在 iPhone 上执行。

手表和 iPhone 按正常情况保持在一起；本功能不要求手表直连 Mac，也不增加 Mac 的局域网协议。

## 非目标

- 不支持 iPhone 不在身边时仅靠手表记录。
- 不新增 watchOS App 或 App Intent。
- 不改变现有 Mac 与 iPhone 的 iCloud、局域网同步格式。
- 不把手表记录伪装成新的 Mac 数据类型。

## 方案

保留现有 `喝水BO～` 捷径作为 iPhone 执行器和 iPhone 上的主入口，并新增 `喝水BO～ 手表`：

1. `喝水BO～ 手表` 只显示数字输入，默认值为 `197`，并校验 `1...2000`。
2. 用户确认后，手表把水量编码为一行文本：`drink:喝水BO～<ml>`，并发送到用户自己的 Apple ID 邮箱。
3. 手表捷径直接把 Apple ID 邮箱文本交给发送消息动作，让 iMessage 解析收件人。这条短消息只作为同一位用户设备之间的传输通道。
4. iPhone 的“收到消息”自动化在消息包含 `喝水BO～` 时立即运行 `喝水BO～`，并把消息内容作为输入；`喝水BO～` 检测到 `drink:<ml>` 输入时直接记录该水量。
5. 没有消息输入时，`喝水BO～` 仍然显示普通的水量输入，不影响手动使用。
6. 手表入口不提供“查看今日记录”，也不增加第二个菜单。
7. 两个捷径安装后，只在手表上显示 `喝水BO～ 手表`，避免用户在手表上直接触发 iCloud 文件动作。

## 为什么拆成两个捷径

现有捷径把输入和 iCloud 文件操作放在同一条动作链里。手表直接运行时，文件操作会触发远程执行，可能报 `remote user isn't registered`。watchOS 26.4 之后，手表里的 `Run Shortcut` 调用另一个隐藏捷径又会频繁报 `Shortcut Not Found` 或在启动时退出。

因此手表端只保留系统支持的数字输入、取整和发送消息动作。消息同步到配对的 iPhone 后，由 iPhone 的消息自动化执行主捷径；保存、iCloud 写入、局域网请求和通知仍然只发生在手机端。

## 设置与失败行为

- iPhone 需要创建“收到消息”自动化，并设为“立即运行”；否则消息只停留在“信息”里。
- 首次使用应在 iPhone 解锁时运行一次 `喝水BO～`，完成 iCloud 文件夹和局域网授权。
- iPhone 不在附近、消息未送达或自动化关闭时，手表不会伪造 Mac 记录；应先检查“信息”中是否出现 `drink:喝水BO～<水量>`。
- 同步成功后的通知继续由 `喝水BO～` 发出。记录仍按现有事件 ID 去重，不会因为经过手表入口而重复统计。

## 安装内容

- 更新现有 `喝水BO～` 捷径，使其接受 `drink:<ml>` 和 `view` 输入。
- 新增 `喝水BO～ 手表` 捷径文件，默认水量固定为 197ml，只保留数字调整和确认。
- Mac 欢迎页分别提供“发送 iPhone 版”和“发送手表版”，并在说明中要求两个都安装、只把手表版显示在 Apple Watch。
- 发布包同时携带两个捷径文件。

- Cherri 编译和现有 ShortcutTests 通过。
- 检查主捷径包含 `ShortcutInput` 和 `drink:` 分支，手表捷径只包含一次数字输入、文本编码和一次 `Send Message`，并且没有 `Run Shortcut`。
- 在 iPhone 上验证原菜单保持不变，以及手表默认 197ml、调整数字、锁定 iPhone 后的手表调用。
- 分别验证同一 Wi-Fi 局域网同步、关闭局域网后的 iCloud 同步、重复运行不重复计数。
